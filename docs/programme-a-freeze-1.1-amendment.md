## 2. Sampling unit, identity, and strata

The sampling unit is a **vendor-operated platform control plane**: an externally
operated service whose API resources belong to one documented tenant/account resource
namespace and common account-level authorization authority. A login portal or corporate
owner alone is not a control plane. A platform can offer several products/categories.
Same owner + a demonstrably different tenant namespace or authorization authority = separate units.
Different brands + shared namespace/authority = one unit. Separate API hosts, SDKs,
product names, API keys, billing plans, or separate consoles alone do not prove separation.
Federated SSO alone does not prove sameness. Parent/subsidiary relationships are recorded
but never themselves merge or split units. No corporate-family exclusion is inferred.

Resolve at snapshot cutoff T0 using first-party identity/account documentation. Record
all source record IDs, historical names, product aliases, operator and ultimate parent
when documented, with evidence. Parent unknown is a reported attribute, not an eligibility
failure. An explicit migration/rebrand within the same control plane is an alias.
Do not infer identity from the rejected builder or remembered vendor facts.

For each asserted pair, record SAME / DISTINCT / UNRESOLVED with evidence. SAME is an
equivalence relation: its transitive closure is a unit. A DISTINCT edge within a SAME
component is a contradiction and blocks the frame. Any UNRESOLVED identity relation or
missing canonical account anchor blocks **the entire Freeze 2**, rather than selectively
removing difficult-to-resolve brands. Do not count unresolved aliases as extra vendors.
This is a structural validation failure, distinct from unresolved eligibility of a known
unit. No pairwise relation may be omitted merely because a name looks unfamiliar.
Pairs sharing an operator, documented parent, account/auth host, alias link, or source
identity identifier require explicit review; all other pairs are DISTINCT provisionally
by disjoint documented control-plane anchors. Contrary evidence reopens the relation
within the uniform search budget; unresolved relations at its end block the frame.

Canonical anchor: the official account-management URI naming the platform namespace;
where several equivalent anchors are documented, use the byte-smallest normalized URI.
Normalization: HTTPS/HTTP kept distinct; lower-case IDNA host, remove default port,
fragment and tracking query parameters (`utm_*`, `gclid`, `fbclid`), retain other queries
sorted by key then value (preserving duplicate pairs), resolve dot segments, preserve path case, remove terminal `/`
except root. Never merge solely by registrable domain. If multiple units share an anchor,
append the documented immutable tenant-namespace/service identifier; absent an unambiguous
identifier, STOP. Canonical ID is lower-case hexadecimal SHA256 of UTF-8 canonical JSON
`["FIRSTCALL-A-1.1-ID", anchor, namespace_id]`;
namespace_id is the empty string when the anchor is unique. Unicode strings use NFC;
IDNA uses IDNA2008. Uppercase percent-escape hex and decode only unreserved characters
before resolving dot segments. Invalid or non-HTTP(S) account anchors block identity
resolution. Display names never key sampling.

Seven strata are now fixed (stable IDs, not alphabetical labels):

| ID | Label | Positive functional membership |
| --- | --- | --- |
| C01 | messaging/email | First-class message submission/delivery objects |
| C02 | payments | First-class payment, transaction, checkout or settlement objects |
| C03 | storage/object | First-class stored file/blob/object resources |
| C04 | identity/auth | First-class account, identity, user, credential or authorization resources |
| C05 | scheduling/calendar | First-class calendar, event, appointment or booking resources |
| C06 | docs/e-sign | First-class authored document, signature request or signing workflow resources |
| C07 | data/CRM | First-class general database records or CRM entities; excludes merely storing one of the other six resource types |

Membership describes publicly documented native product functions, not agent difficulty,
documentation quality, number of users, or whether that category's journey seems easiest.
Incidental internal functions (every product stores files/users) and functionality a
customer could build atop generic compute do not establish membership. Multiple native
functions can qualify. Determine the complete membership vector with TRUE / FALSE /
UNRESOLVED for every category under §4. One unresolved membership makes eligibility
UNRESOLVED_ELIGIBILITY; affirmative absence from all seven is EXCLUDED / SCOPE_OUTSIDE.
Positive capability in any stratum must still satisfy every Freeze-1 inclusion criterion;
category membership itself never certifies a safe effect.

An affirmative FALSE membership requires a documented complete product scope or explicit
negative capability statement, not a missing navigation link. For a fully resolved
nonempty membership set, score each applicable stable ID with
SHA256(canonical JSON `["FIRSTCALL-A-1.1-STRATUM", canonical_id, category_id]`). Assign the
lowest unsigned 256-bit score; break an actual digest tie by stable ID bytes. This literal
domain separator is a public fixed algorithm constant, **not a randomisation seed**.
Canonical JSON means UTF-8, sorted object keys, compact separators, ensure_ascii=false,
no NaN; the specified inputs are arrays of strings. No salt, reroll, category-count
balancing, manual override, or display-name dependence is permitted. Freeze this mechanism
before source discovery. Seal the complete identity and membership ledger before computing
any category hash; adjudicators never see hash scores or hypothetical assignments. It
assigns overlapping units without sorting display labels; no balancing or probability
guarantee is made about its fixed realized assignment.
Conditional draw probabilities are calculated from the resulting frozen strata (§6).

## 4. Uniform documentary adjudication and terminal states

Keep Freeze-1 substantive inclusion and safety requirements. Each inclusion and exclusion
predicate is TRUE / FALSE / UNRESOLVED with captured evidence, source URL/hash, excerpt,
retrieval time, effective date where stated, and adjudicator reason. A public page existing
does not establish every other criterion. A free tier, a trial, nondelivery or reversible
deletion alone does not establish a durable independently verifiable sandbox-safe effect.
No vendor accounts, authentication, credentials, API requests, trials or feasibility probes.

Permitted evidence: frozen enumeration metadata for identity leads; first-party public
documentation, pricing/signup/terms/account-help and official deprecation notices for
eligibility; official legal/control-plane documents for identity. A dated public archive
of such a page is permitted with provenance. Search snippets, model memory, reviews,
forums, rankings and the rejected builder cannot establish predicates. Documentary status
is as observed in a single seven-calendar-day capture window beginning after source lock;
it is not falsely backdated to the source snapshot T0. Finish the entire batch within that
window or STOP. No rolling per-vendor extension. Subsequent changes go into a reported
post-frame change log and never silently rewrite decisions.

Build a per-unit deterministic frontier from the union of source-provided official docs
and product URLs (normalized and byte-sorted), followed breadth-first by first-party links
whose URL path contains one of: `doc`, `api`, `reference`, `sandbox`, `test`, `free`, `pricing`,
`signup`, `sign-up`, `account`, `auth`, `tenant`, `terms`, `region`, `privacy`, `deprecat`.
Resolve redirects (max 3), strip fragment/tracking fields, and visit each URL once. An
external documentation host is first-party only if linked as official by a frozen lead.
At each depth sort normalized URLs by bytes; max depth 2, max 16 distinct pages per unit,
max 2 MiB/page, 30 seconds/request, one retry only for timeout/429/5xx (retry after 30 s).
Failed, blocked or oversized pages consume a slot and remain evidence gaps; archive error
metadata without credentials. No web searches, guesswork URL construction or discretionary
extra pages. Source row pages already captured count as leads but only official pages
visited for the unit count toward its 16-page budget. Shared pages may be cached once but
count equally for every unit that uses them. Identity uses the separate, non-circular capture stage specified in §8.3;
these 16 pages are the subsequent canonical-unit eligibility/category budget. Stop at exhausted frontier, depth/page cap, or batch deadline.
Collect the whole permitted frontier even when an exclusion is found early, to avoid
unequal effort and hiding multiple reasons. Record all attempts and budget consumption.
Non-English pages remain in scope; use one pinned translation tool/version for all such
pages, retain originals/translations and hashes; uncertain translation remains UNRESOLVED.

Two independent documentary adjudicators receive identical captured packets, no prior
outcomes, no category totals, and no draw/ordering. They code each predicate and category
membership using this checklist; neither can request additional evidence. Agreement on
TRUE/FALSE is adopted. Any disagreement, contradictory authoritative evidence, insufficient
scope, uncertain date, or inaccessible evidence is UNRESOLVED. There is no tie-breaking
researcher discretion. Identity disagreement blocks the frame under §2. For purely
mechanical source extraction/hashes, disagreement is a validation failure, not a vote.
Each adjudicator has at most 60 active review minutes per resolved unit for eligibility,
category and translated evidence review; identity has the separate §8.3 budget. Log consumption. Unfinished predicates are
UNRESOLVED. No extra reviewer, second pass, or extension for preferred units. Source
metadata screening has a uniform 20 active review minutes per source per adjudicator;
unfinished source predicates block source lock. Adjudicator identities, checklist and
translation version are registered before packets are opened and cannot change per unit.

After identity resolution, every canonical unit receives exactly one terminal frame state:

- **EXCLUDED**: an agreed affirmative exclusion, an agreed affirmative violation of a
  required inclusion predicate, prior-target provenance under §5, or SCOPE_OUTSIDE. Record
  every applicable reason, not only the first. An affirmative exclusion takes precedence
  over unrelated unknown predicates. A known inclusion violation is `INCLUSION_FALSE:I1`
  through `I4` with the exact frozen requirement; silence cannot support it.
- **ELIGIBLE**: all required inclusions affirmatively established, no exclusion true or
  unresolved, prior-target audit complete/negative, and all category memberships resolved
  with ≥1 applicable stratum. Assign exactly one stratum by §2.
- **UNRESOLVED_ELIGIBILITY**: neither of the above. It is a recorded third terminal state
  for this snapshot, not a claim of scientific ineligibility. Record every missing or
  disputed predicate. Do not insert it into the draw or reserve ordering.

Canonical conservation: **TOTAL_CANONICAL_UNITS = ELIGIBLE + EXCLUDED +
UNRESOLVED_ELIGIBILITY**. Raw conservation: **TOTAL_SOURCE_ROWS = sum(alias-row count
over canonical units)**; every row maps once, every unit has ≥1 row, no duplicate canonical
identity. Structurally unresolved identity/extraction blocks these equations rather than
creating a fourth population state. Report identity failures separately as a blocked build.

Unresolved and excluded units are outside the eligible-frame estimand, never scored as
failures and never counted as launched runs. Publish counts/fractions against the canonical
union, predicate-specific missingness, evidence budgets and category memberships (unknown
stratum separately). Freeze-1 run-level UNKNOWN is unchanged and distinct. No post-lock
search upgrades, reserve promotion, or replacement of unresolved units. New evidence may
only support a separately preregistered later frame/cohort; retain the original ledger.

## 6. Allocation, probabilities, replacements and denominators

Let M_h be eligible units in stratum h and M their sum. N remains 24. Allocate seats using
Hamilton proportional apportionment: b_h=floor(24*M_h/M), distribute 24-sum(b_h) extra
seats to largest integer remainder (24*M_h mod M); ties use the §2 hash formula with
domain `FIRSTCALL-A-1.1-ALLOCATION` and inputs `[domain, category_id]`. An actual hash tie
uses stable ID. This is the only use of category counts in design; category definitions,
membership and identity assignment never depend on counts. Freeze 2 fails if any of the
seven strata gets zero seats or lacks m_h+ceil(m_h/4) eligible units. No collapsing strata,
quota tweaking, source additions or N reduction to repair a failed frame.

At the later blind draw, each category has a uniform random permutation of its canonical
IDs; first m_h are initial selections, the entire remaining permutation is reserve order.
For exact, auditable randomization, the later `RANDOMISATION_SEED` is a randomness tape
of exactly 32*M independent uniform bytes (not a short PRNG key). Generate it once, only
after the complete frame/method is sealed, from the registered operating-system entropy
interface `os.urandom(32*M)` in one call; record OS/Python versions and commit SHA256 of
the raw tape bytes before interpreting it as ordering. On entropy failure STOP, with no
fallback entropy source. In global
byte-sorted canonical-ID order, assign each unit its successive 32-byte unsigned big-endian
priority. Within each stratum sort ascending priority. Any tied priority within a stratum
halts the cohort: no deterministic identity tie-break or reroll. Conditional on no tie,
exchangeability gives an exactly uniform permutation under the stated uniform-entropy
model. No finite-PRNG exact-uniformity claim is made. Tape length, mapping, commitment and
collision checks must be validated offline before generation; display names never key
the draw. Reveal the tape only at Freeze 5. This explicitly replaces Freeze 1's salted
vendor-name hash ordering. This amendment creates no tape, seed, permutation, list, or
actual quota table.

Probability justification: independent identically distributed priorities are exchangeable;
conditioning on no within-stratum tie preserves exchangeability. Each unit therefore has
m_h of M_h possible selected positions. Restricting that same uniform permutation to a
complete, order-blind census subset leaves a uniform permutation of its G_h members,
giving m_h/G_h. The result depends on gate independence from priority and complete census
coverage; missing census values do not justify substituting an estimated G_h.

Initial first-order inclusion probability is pi_i=m_h/M_h; selected-plus-first-r reserves
probability is (m_h+r_h)/M_h (capped at 1), where r_h=ceil(m_h/4) is the minimum planned
reserve budget. Full reserve ordering does not mean all units were selected. Publish
M_h, m_h, r_h, canonical ordering, algorithm version and probabilities with the sealed
frame/method; reveal lists only at the parent protocol's permitted stage. No inference
to vendors outside the enumerated, resolved, eligible union is supported.

Replacement remains same-stratum and next-in-order, only for affirmative pre-execution
ineligibility under frozen gates, never agent outcomes or convenience. To make final

No search/safety threshold may be relaxed to fill a quota. These later checks are not

Take the first m_h census-eligible units in the already frozen permutation, logging each

dispositions; never report initial probabilities as the final ones. The census does not
authorize feasibility optimization, task simplification, or agent trials.

The operational estimand population is explicitly the census-eligible subset of the

inverse-final-inclusion-probability weights w_i=G_h/m_h. If all sampled vendor rates are

### 8.1 Deterministic category assignment, not random assignment

For a fixed canonical ID and membership set A, assignment probability is 1 for the
chosen category and 0 for every other category. A claim of 1/|A| is NOT justified for
this fixed public SHA256 function. In an ideal independent-hash thought experiment,
conditional on distinct scores, symmetry would give 1/|A|; deterministic tie-breaking
would break that exact claim without conditioning. Neither assumption is needed here.
The rule remains an outcome-independent deterministic partition. The argmin of
(digest, stable ID) is invariant to input order and display-label changes with IDs held
fixed. It is not invariant to changing the IDs' meanings, which is forbidden after seal.
No modulo reduction is used for category assignment. Hamilton's integer remainder is
deterministic seat apportionment, not a conversion of entropy, so modulo bias is inapplicable.

Validate canonical IDs as exactly 64 lower-case hex characters and category IDs as the
unique set C01–C07 with the meanings in §2. Reject duplicate, unknown, empty or malformed
membership IDs, repeated canonical identities and unequal identity preimages sharing
a digest; do not silently deduplicate malformed inputs. Membership must be nonempty and
fully resolved before assignment. Category-domain and identity-domain strings include
version 1.1; allocation uses its separate declared domain. All preimages are retained.
After the identity/membership seal, alias additions, changed anchors, new evidence about
membership, or discovered duplicates invalidate the cohort rather than changing an ID
or reassigning a stratum. No new draw is permitted under that cohort identifier.

Public deterministic hashing cannot cryptographically prevent a dishonest adjudicator
from privately computing scores. The defensible claim is reproducibility under the
locked evidence/checklist and no-score-access procedure, not impossibility of collusion.
Any score inspection or evidence manipulation before ledger lock is a documented halt.

### 8.2 One authoritative source-discovery capture

The previous live-query procedure does NOT guarantee the same results for independent
researchers at the same date. Index changes, server routing and experiments can change
results despite the language/country settings. Reproducibility is therefore explicitly
defined conditional on **one authoritative archived capture**, not a repeatable live query.

The Freeze-1.1 sealing certificate names one capture custodian and one registered runner
(code digest, runtime/browser version, user-agent, network-egress identity and request
settings), before any discovery response is obtained. This is administrative registration,
not permission to choose catalogs. Start at 09:00:00 UTC on the prescribed next UTC day;
issue the four queries in their listed order at offsets 0, 60, 120 and 180 seconds, each
requesting 20 organic results with the same logged-out GB/English settings. No preview,
alternate runner, pagination experiment or substitute session is allowed. A request
starting more than five seconds late, unavailable result page, or fewer than 20 parseable
organic positions stops the capture. Archive raw responses before parsing them and
publish the ordered response hashes and session manifest immediately after the fourth
request, before screening any source. The first registered attempt is authoritative even
if it fails; no repeat to seek better search results. Network failure produces a halt.
All researchers must use these exact archived bytes and subsequent sealed decision
ledger. An independently rerun search cannot replace or augment the capture. Two teams
using different live responses have not reconstructed this cohort's protocol input.

Source screening follows the fixed four-page/20-minute procedure on that archive's
result URLs, in normalized URL byte order. Both source adjudicators must agree on every
predicate; disagreement is SOURCE_UNRESOLVED unless a different agreed affirmative
failure already establishes SOURCE_INELIGIBLE. Qualifying source owner/format/version
decisions and every rejected result are committed before candidate downloads. Alternative
interpretations challenge that ledger and halt use; they do not yield an interchangeable
source universe. Report search-capture and human-adjudication dependence as limitations.

### 8.3 Non-circular identity capture and explicit boundary cases

The earlier per-platform identity budget was circular: platforms were not yet known.
First group source rows only by their identical normalized product/docs lead-URL set.
Each distinct lead group gets the same 16-page/depth-2 capture and 60-minute identity
review budget per adjudicator, without asserting these groups are sampling units.
Traverse groups in byte order of canonical JSON lead sets, and paths by the fixed BFS;
mandatory caching shares identical response bytes. After this identity stage, resolve
units and then run the separate 16-page/60-minute eligibility/category stage on each
canonical unit. Repeated catalog entries cannot buy extra eligibility pages. Publish
identity-stage lead counts and access budgets, including the advantage of more distinct
documented aliases; this source-coverage effect is not hidden as uniform identity effort.
Both stages share the seven-day global capture window, starting 00:00 UTC the day after
source lock; within each stage use one registered scheduler and byte-ordered traversal.
Missing the batch deadline blocks the entire batch, not just whichever units were last.
HTML retrieval uses raw response hyperlinks, no scripts/clicks or discretionary archive
fallback. A permitted archived page must itself be a frozen lead/link; no archive search.
Non-HTML supported documents are evidence leaves with no link expansion. Fixed technical
parsers and translation version are registered before any packet is opened. Unsupported
formats consume a slot and leave evidence unresolved. Within each stage, complete capture
before that stage's review; identity review necessarily precedes canonical-unit capture.

Namespace means the platform's **account-wide administrative tenant scope**, not individual
customer tenants, API resource collections or version-specific endpoint namespaces.
Authorization authority means who grants that tenant's platform permissions, not its
federated login issuer. SAME requires affirmative equality of both scope and authority;
DISTINCT requires affirmative difference of either; otherwise UNRESOLVED. Merely different
URLs cannot establish DISTINCT. The §2 provisional-distinct-by-anchor shortcut is removed.
Every source-row pair must have a recorded relation or a mechanically reproducible relation
derived from documented scope/authority identifiers; unresolved pairs block the frame.

- Several APIs or brands sharing both account scope and permission authority: one unit.
- Subsidiaries sharing login/permission machinery but having separate account scopes:
  distinct only with affirmative scope evidence; ownership or SSO is insufficient.
- Acquired products: ownership changes alone do nothing; actual documented control-plane
  integration changes identity only if effective by T0. Post-lock integration halts the
  cohort; it never authorizes retrospective merging or reserve substitutions.
- Regional hosts with one global administrative account: one unit. Independently enrolled
  regional account scopes are distinct; region spelling alone supplies no evidence.
- White-label/reseller brands merely exposing the same upstream account scope and
  permission authority are aliases. A separately operated customer-administration scope
  or permission authority is distinct, even if it resells upstream infrastructure.
- API versions sharing the same account scope and permission authority are aliases.

Unknown historical status at T0 blocks identity resolution; current docs must not be
silently treated as evidence of an earlier acquisition/integration state. Normalized
anchors are identifiers of already-resolved units, not evidence that two units differ.

### 8.4 Provenance-only designation extraction

The former phrase 'vendor-specific path' was too interpretive. A path alone now only
triggers examination; it never creates an exclusion. Positive additional designation
requires a tracked configuration/manifest with an explicit experiment identifier and
a literal `vendor`, `vendor_id`, `target_vendor` or `target_vendor_id` field at the same
experiment-object level, or an experiment-design document's explicit Target/Targets or
Experimental target(s) heading/table assigning that identity to the experiment. An
explicit FIRSTCALL-authored/operated declaration in such a design/configuration is also
positive evidence. A mention elsewhere, dependency, example, bibliography or path-token
match is insufficient. Match the designated identity to the canonical platform using
the identity ledger, never a fuzzy name substring or corporate-parent expansion.

The finite positive grammar is: a JSON experiment object has a nonempty string
`experiment` or `experiment_id` and a nonempty string in one of the four identity keys;
Markdown has an explicit `Experiment: <identifier>` metadata line and a Target/Targets
or Experimental target(s) heading containing a `Vendor:`/`Target vendor:` identity line
or a table column headed `Vendor`/`Target vendor`. Heading/field labels are case-folded,
trimmed and may have a leading numeric section label; identity values are preserved.
Authorship/operation must use explicit `firstcall_authored: true` or
`firstcall_operated: true` associated with that experiment/identity. Code-to-design
association requires a literal runner/verifier path reference in the qualifying record.
Other layouts are not silently read semantically: record UNRECOGNIZED_DESIGNATION and
block registry completion until a separately prospective amendment, not an ad hoc parser
extension. Receipt/result sections are never eligible positive-designation contexts.

Project the entire parent-commit tracked path inventory under `experiments/`, `docs/`
and `firstcall/` in byte order. Configuration/manifest projection emits only experiment
identifier plus those four identity keys and explicit authorship/operation declarations.
Markdown projection emits target-designation headings and their identity column/line,
not result columns. Receipts, traces, outcomes, retrospective/forensic documents and
result sections are excluded from projection, not read for evidence. Code paths emit
only the pathname and any associated qualifying design/configuration reference; code
execution and result reads are forbidden. Record every path's projection or exclusion
reason and hash so nobody can cherry-pick which designs were examined. Unrecognized
designation layouts or inability to project without results blocks registry completion;
absence of a parseable designation is not permission to ignore a plausible target file.
The two fixed reviewers must agree; ambiguous designation or identity blocks the registry.

Thus reconstruction is from the fixed repository plus the complete sealed projection
ledger and explicit role evidence, not arbitrary documentation name searches. This is
an audited documentary decision procedure, not a claim that natural-language semantics
can be inferred infallibly by filenames. The named parent exclusions remain mandatory.
No exclusion registry or additional named target was constructed during this review.

### 8.5 Entropy custody, fixed census, and inclusion probabilities

M_h counts canonical ELIGIBLE units assigned to h in the sealed Freeze-2A frame; M is
their sum. M, all IDs/preimages/memberships, quotas and algorithm digests are known and
committed before entropy. G_h counts those same units passing the complete Freeze-5A
pre-execution census; it cannot contain new units or unresolved/excluded frame members.
Frame/census sizes and accepted sets are not estimated from the finally selected sample.

Keep the OS-entropy mechanism; replacing it with a public beacon is not necessary for
exchangeability. A beacon would improve external auditability of entropy provenance but
would introduce a new source/timing/failure mechanism. Private entropy needs custody:
one registered independent custodian, with no source/identity/eligibility/apparatus role,
executes the sealed one-call generator under an independently witnessed process log.
It writes the raw tape to access-controlled custody, publishes its SHA256 and the frame
digest before any block interpretation, and logs every failed attempt. Generator error,
short tape, failed commitment, changed frame, or repeat invocation aborts the cohort.
The cohort identifier is bound to the Freeze-1.1 seal and cannot be recreated to reroll.
No promise that a hash alone proves honest OS entropy or prevents concealed fraud is made.

For sorted unique canonical IDs u_0,...,u_(M-1), u_j receives bytes [32j,32j+32).
Check the exact 32M length, one-to-one block coverage and all ID uniqueness before sorting.
No cross-stratum tie matters; a within-stratum priority tie aborts without redraw. Under
independent uniform bytes, each permutation of M_h priorities is equally likely conditional
on no tie. The independent disjoint stratum blocks remain independent conditional on
their no-tie events. This proves pi_i=m_h/M_h, conditional on a successful draw gate.
Unconditionally, multiplying by the probability of that gate is necessary; do not present
the conditional expression as a probability over aborted cohorts.

Custody reveals neither tape, priorities, ordering nor derived run schedule to identity,
mapping, eligibility or census personnel until the complete census ledger is sealed.
The mechanical Freeze-3 draw runs in custody and releases only its commitment. Freeze 4
locks all-frame mappings, fixtures, factual pre-execution gate predicates and their uniform
budgets while still blind. Freeze 5A applies those gates once to every eligible unit, seals
all decisions and G_h, and only Freeze 5B reveals/reconciles the tape/order. No appeals,
second eligibility pass or additional setup to rescue an inconvenient census result.
Any post-census eligibility change, safety issue or newly discovered alias halts this cohort;
no further replacement is allowed after census sealing or execution begins. Apparatus
faults cannot be relabelled vendor ineligibility to select another unit.

For an order-independent fixed census subset, restricting a uniform permutation to its
G_h members is uniform: each subset ordering has the same number of extensions to M_h.
Thus every census-eligible i has pi_i=m_h/G_h; census-ineligible units have final pi=0.
For distinct i,j in one stratum, pi_ij=m_h(m_h-1)/(G_h(G_h-1)); across strata pi_ij=pi_i*pi_j.
Use M_h in the corresponding initial-design formula. Singleton population strata have
no distinct within-stratum pair; formulas with zero pair denominator are inapplicable.
The main point estimator needs first-order probabilities; design variance formulas may
need pi_ij. The conservative band below does not require estimating joint probabilities.
If G_h<m_h or any census status is unresolved, execution stops independently of priority.

### 8.6 Explicit estimand support and valid uncertainty claim

**P_v describes the equal-platform mean of conditional PROVEN_SUCCESS probabilities
for canonical platforms in the sealed source-union frame that have fully resolved
documentary eligibility, are in the seven declared categories, pass the provenance-only
prior-target exclusion and the UK-customer sandbox/effect criteria, and pass the complete
order-blind pre-execution census, under the frozen natural customer run condition.**

'Conditional' means given a valid, determinate run, matching Freeze 1's success denominator.
This explicitly corrects the former unconditional-probability wording; it is not a claim
that UNKNOWN runs succeed or fail. Define p_i=Pr(PROVEN_SUCCESS | valid and determinate,
platform i), and P_v=mean_G(p_i). This parameter requires positive determination probability
for each unit; a structural zero makes the full-population conditional parameter undefined,
not permission to delete that platform. Five indeterminate trials do not prove a structural
zero. Report unidentified/undefined population conclusions and missingness rather than
asserting unbiased full-population estimation. The weighted complete-case ratio remains
the reported point summary, labelled a conditional/partial estimate when vendors are
indeterminate. Do not silently redefine G to the observed complete cases.

Compared with Freeze 1, support is expressly changed by the control-plane unit, seven
fixed categories, bounded captured source union, UK access context, unresolved non-entry,
expanded provenance-only exclusion and complete census restriction. The safe-effect
requirements themselves are unchanged. M→G removes prospectively tested ineligible
units but also narrows the operational target population; it is not mere bookkeeping.

The former within-stratum bootstrap was not a guaranteed 95% interval and can degenerate
when m_h=1 or observed rates coincide. Replace its **primary** interval claim as follows.
Let n_i be valid determinate runs among the fixed k=5 attempts. Put L_i=U_i=r_i=S_i/n_i
if n_i>0; otherwise L_i=0, U_i=1. These are uncertainty endpoints, not scored outcomes.
Let W_h=G_h/G, a=sum_h W_h*mean_sample_h(L_i), b=sum_h W_h*mean_sample_h(U_i), and
C=sum_h W_h^2/m_h. Report [max(0,a-e), min(1,b+e)] with e=sqrt(C*ln(40)).

Coverage assumptions are explicit: the design is stratified SRS as proved above;
platform run clusters are independent conditional on the frozen environment/schedule,
with cluster laws unaffected by selection priorities or which other units were sampled;
and E[r_i | n_i>0]=p_i under the fixed run protocol (e.g. independent identically
distributed categorical trials per platform suffice). Conditional means must exist.
Then E[L_i]≤p_i≤E[U_i]. A without-replacement Hoeffding bound for sampling the fixed
cluster means and a conditional bounded-cluster Hoeffding bound for run noise give,
for either endpoint, one-sided tail at most exp(-t^2/C). Union at t=e gives ≥95%
coverage of P_v. This conservative two-stage bound uses no finite-population correction
and remains valid for single-seat strata and census strata under those assumptions.
It does not guarantee useful width at N=24, nor robustness to dependent platform shocks
or informative within-platform determination violating the conditional-mean assumption.
If those assumptions are not defensible, label the interval uncalibrated; do not claim
95% coverage or choose a different method after results. An entirely unidentified
population receives [0,1] and no point claim. Raw UNKNOWN assignment bounds remain
separate descriptive sensitivity results; they are not this conditional-parameter CI.

Retain the within-stratum bootstrap only as a secondary descriptive sensitivity:
exactly 10,000 replicates, resample m_h vendor clusters with replacement in each stratum,
retain their frozen weights and recompute the complete-case ratio. Use nearest-rank
2.5%/97.5% endpoints (ceiling(p*10000), one-based). If any replicate has undefined
denominator, report the descriptive interval null and the count; never drop/redraw such
replicates. Degenerate intervals are labelled empirical degeneracy, not certainty about
P_v. The deterministic bootstrap seed is SHA256(canonical JSON
["FIRSTCALL-A-1.1-BOOTSTRAP", final_frame_digest]); it is computed only at the later
method stage and is not the vendor-draw entropy. The stream is SHAKE256 of UTF-8
`FIRSTCALL-A-1.1-BOOTSTRAP-STREAM`, one NUL byte and the raw seed digest. Consume successive
unsigned 64-bit big-endian words x; accept only x < 2^64-(2^64 mod m_h), then index
the sorted selected cluster IDs by x mod m_h. Traverse replicate, stable stratum ID and
draw slot in ascending order. Rejection removes integer-mapping modulo bias under the
uniform-word model; no exact-randomness claim is made for this deterministic descriptive
bootstrap. This algorithm is fixed now; implementation is tested at Freeze 2. Joint probabilities above permit separate design
diagnostics; no unregistered variance estimator becomes the primary interval.
